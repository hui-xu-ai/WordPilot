# ADR-004 参考文献身份与中间层存储：CSV 唯一事实源 + 派生索引

- 状态：accepted
- 日期：2026-10-24
- 相关：`src/plugins/reference/`、`docs/PLUGIN_GUIDE.md`

## 背景

要做一个「参考文献助手」：光标停在 Word 的引用处，旁边弹出该文献的信息与**用户自己的备注**。
约束来自实际使用：

1. 备注必须**绑定在文献身份**上，不能绑在文档位置或编号文本上 —— 用户会另存新版本继续改；
2. EndNote / Zotero 的接口形态差异大，且可能没装、没开、版本不兼容；
3. 用户要能**自己维护**这份数据（Excel 手改、整份替换），所以不能只存数据库；
4. 实测两个真实文档：Zotero 文档有 122 个带完整元数据的域；EndNote 文档 1973 个域里只有 7 个
   `ADDIN EN.JS.CITE` 且**内部没有 XML 数据**（已被转纯文本），另有 22 个 `REF _Ref…` 交叉引用。

## 决策

1. **身份键（`ref_key`）**
   - 有 DOI 用 `doi:<doi>`（跨库迁移最稳），否则 `zotero:<item id>` / `endnote:<rec-number>`；
   - 脚注/尾注用正文哈希 `doc:<文档名>:fn|en:<sha1(正文)[:10]>`（复制/重编号不错位）；
   - 交叉引用用书签 `doc:<文档名>:ref:<书签名>`；
   - **不用** `citationID`（每次插入都变）、文档字符位置、正文哈希（改一字就失配）；
   - 一条文献允许多个**别名**，任一命中视为同一篇（Zotero 换 EndNote 重插也不丢备注）。
2. **存储：CSV 为唯一事实源**
   - `config/references/references.csv`（文献 + 备注，用户手改主战场）、
     `anchors.csv`（文档里"哪处引用→哪条文献"，程序维护、可手改）；
   - `utf-8-sig`（Excel 双击不乱码）、tmp + `os.replace` 原子写、每次写前 `*.bak-<时间戳>`（保留 10 份）、
     `mtime+size+首行哈希` 检测外部替换后自动重载且**不回写覆盖**。
3. **SQLite 只是派生索引**（`index.db`）：CSV 指纹变化就重建，可随时删除，永远不是第二个事实源。
4. **不回写 EndNote/Zotero**：只做"可选元数据补全"，接口挂了不影响主功能。

## 备选与否决理由

| 方案 | 否决理由 |
|---|---|
| 纯 SQLite 作源 | 用户无法用 Excel 手改/整份替换；跨机器共享要工具 |
| 直接连 Zotero `zotero.sqlite` / EndNote `.enl` | 接口随版本变化、库被占用时打不开、且用户明确要求"中间层" |
| 用文档位置/编号文本作身份 | 另存新版本、插入新引用即失效（正是用户要避免的问题） |
| 把备注写回文献库的 Notes 字段 | 用户明确不需要；且会污染用户的库 |

## 后果

- 正面：备注在"另存新版本/换引用工具/换电脑（拷 CSV）"下都不失效；离线可用（不要求 Word 或文献软件在跑）；
  用户能像编辑表格一样维护自己的文献与备注。
- 负面：用户手改 CSV 时若改坏（删列/乱码）需要容错与备份来兜；`anchors.csv` 在用户整份替换文献库后
  会出现"孤立锚点"，需要主页面的重新绑定流程（已实现）。
- 性能实测：38.4 MB 文档扫描 71 ms、100.3 MB 文档 151 ms；索引查询毫秒级。
