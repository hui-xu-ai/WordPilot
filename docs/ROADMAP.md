# 路线图 · ROADMAP

修订于 2026-10-14。基于用户反馈确定的产品哲学：**极简、低 token、不打断写作、离线优先、按身份绑定**。

## 指导原则（做任何功能前先过一遍）
1. **不打断写作**：扫描/读取尽量离线（读 .docx 磁盘文件），不把 COM 逐条戳活文档当默认路径。
2. **极简**：现有通用 AI 工具能做的（整段润色、批量导出）不在此重造。
3. **低 token**：不引入领域词表、不加宽上下文、不生成修改理由。
4. **按身份绑定**：用户数据（如文献笔记）绑到稳定身份（Zotero itemKey / EndNote rec-number），跨文档跨版本不失效。

## 已决定不做（用户否决）
修改理由/解释、加宽上下文、领域词表、整段/全文批量润色、批量导出、复杂 agent、迁移 Responses API。
> 注：`mark_text_differences` 的差异外扩、单句窄上下文是**故意设计**，不改（见记忆 project-design-intent）。

## P0（投入小、直接改善日常体感）

### P0-1 题录/引用改为离线读取
- **状态**：原型已验证 `tools/offline_docx_scan.py`（2ms 级、零 COM，能抽题注+分组+Zotero/EndNote 引用+文献表）。
- **待办**：等用户用真实论文验证域格式 → 把 `word_navigator_dialog` 的扫描从"COM 逐条 Item(i)+Information(3)"换成离线解析；跳转仍用单次 COM。
- **消除的问题**：保存后自动刷新时 `_load_from_cache()` 同步取页码导致的 Word/鼠标卡顿。
- **验证**：真实论文上题注文本/编号/页码与 Word 一致；大文档耗时可接受；刷新时前台写作无卡顿。

### P0-2 有错/无错/无反应 三态可区分
- **问题**：现在"无差异就隐藏卡片"，用户分不清"没错"还是"软件没干活"。
- **待办**：常驻悬浮按钮做状态灯——灰=未监控 / 蓝呼吸=请求中 / 红点=发现错误 / 绿闪=检查过无错 / 橙⚠=API失败或无反应。
- **验证**：三种情形肉眼可辨，不额外弹窗。

### P0-3 快捷键验证与补全
- **待办**：先验证现有 4 个全局键（`Ctrl+Shift+E/Z/T/R`，`hotkey_manager.py`）是否真生效（`keyboard` 库可能需管理员权限，或 Word 吃掉组合键）；再给建议卡片补"采纳/忽略"键。
- **坑**：卡片操作键**不能用 Enter/Esc**（全局热键会拦掉正常打车的回车），用 `Ctrl+Shift+Y`(采纳)/`Ctrl+Shift+N`(忽略) 之类不冲突组合。

## P1（价值高、工作量中等）

### P1-1 参考文献"身份笔记"
- **目标**：光标停在引用上标 → 浮出《标题》+ 用户笔记；点一下可编辑。笔记按 **Zotero itemKey / EndNote rec-number** 存本地库，**跨文档跨版本跟随文献本身**（解决用户担心的增删文献、多版本导致笔记失效）。
- **依赖**：P0-1 的离线读取器提供引用 id/标题；真实论文确认 id 可稳定提取。
- **零 token**，纯本地。
- **验证**：同一文献在不同文档/不同引用处都能调出同一条笔记。

### P1-2 题注按章节分组（UI）
- **目标**：导航列表按 章 → 节 分组展示（毕业论文图多时便于定位）。原型已实现分组数据结构，待接入 `word_navigator_dialog` 的列表 UI。

### P1-3 多模型可切换
- **目标**：`api_client` 的 `base_url`/`model` 走配置，设置界面可选厂商+模型（DeepSeek / OpenAI 兼容 / GLM…）。协议不变，仍 Chat Completions。
